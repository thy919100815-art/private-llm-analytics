## 3. Mathematical Re-Derivation & Profile Audit

### 3.1 User Prevalence (`user_prevalence`)
- **Privacy Unit**: Individual enterprise user trajectory within observation window.
- **Adjacency**: Add/remove single user $u$ ($D \sim D'$).
- **Per-User Contribution**: Binary participation indicator vector $b_u \in \{0, 1\}^D$, where $b_{u,j} = \mathbb{I}[m_{u,j} > 0]$, $D$ is the number of taxonomy cells, and participation is bounded by $k = \text{max\_cells\_per\_user}$.
- **Contribution Bounding**:
  $$\|b_u\|_0 \le \min(k, D) \implies \|b_u\|_2 \le \sqrt{\min(k, D)}$$
- **Sensitivity Truth**:
  - The **tight domain-aware maximum** vector count sensitivity is $\Delta_2 = \sqrt{\min(k, D)}$. When $D \ge k$ (e.g. $D = 9, k = 9$), these coincide ($\Delta_2 = 3.0$).
  - Production calibrates using the **valid conservative $L_2$ sensitivity bound**:
    $$\Delta_2 = \sqrt{k}$$
- **Mechanism**: Analytic Gaussian Vector Mechanism adds noise directly to the aggregate count vector:
  $$\tilde{S} = \sum_{u} b_u + \mathcal{N}(0, \sigma^2 I_D)$$
  with $\sigma$ calibrated conservatively to $\Delta_2 = \sqrt{k}$ and $(\epsilon, \delta)$.
- **Post-Processing**: Clamps noisy counts $\hat{S}_j = \max(0, \tilde{S}_j)$, then divides by the public eligible population denominator $N_{\text{public}}$ and clamps rates to $[0, 1]$:
  $$\hat{p}_j = \text{clip}\left(\frac{\hat{S}_j}{N_{\text{public}}}, 0.0, 1.0\right)$$
- **Rate-Vector Sensitivity**:
  - Tight rate-vector bound: $\frac{\sqrt{\min(k, D)}}{N_{\text{public}}}$.
  - Conservative production calibration bound: $\frac{\sqrt{k}}{N_{\text{public}}}$.
  - Coordinate-wise sensitivity of an individual cell rate: $\frac{1}{N_{\text{public}}}$.
- **Audit Finding**:
  - Implementation: **CORRECT & CONSERVATIVE** (`sensitivity()` returns $\sqrt{k}$).
  - Documentation: **IMPRECISE CLAIM IDENTIFIED & CORRECTED**. Earlier release text claimed "exact sensitivity $1/N_{\text{pop}}$", confusing vector count calibration with single-coordinate rate sensitivity, and omitting domain bounds. Corrected in documentation and release notes.

### 3.2 User-Normalized Share (`user_normalized_share`)
- **Privacy Unit**: Complete user trajectory.
- **Adjacency**: Add/remove single user.
- **Per-User Contribution**: $L_1$-normalized share vector $x_u = m_u / \|m_u\|_1$ for non-zero users, and $0$ for inactive users.
- **Contribution Bounding**:
  $$\|x_u\|_1 \le 1.0 \implies \|x_u\|_2 \le \|x_u\|_1 \le 1.0$$
- **Sensitivity**: Exact $L_2$ sensitivity is:
  $$\Delta_2 = 1.0$$
- **Mechanism**: Analytic Gaussian Vector Mechanism on bounded sum $\sum_u x_u$ with sensitivity $\Delta_2 = 1.0$.
- **Post-Processing**: Coordinate-wise non-negative clamping followed by simplex renormalization:
  $$y_j = \max(0, \tilde{V}_j), \quad \hat{s}_j = \frac{y_j}{\sum_{i} y_i} \quad \left(\text{uniform } \frac{1}{D} \text{ if } \sum_{i} y_i = 0\right)$$
- **Audit Finding**:
  - Production DP Implementation: **CORRECT**.
  - Legacy Metric Layer Compatibility: **LOW-SEVERITY NON-PRIVACY DEFECT IDENTIFIED & FIXED**. In `metrics/normalized_share.py`, the zero-sum fallback previously hardcoded `np.ones(9)/9.0`. This was updated to `np.ones(d_cells)/d_cells` and verified with a dedicated regression test.
  - Documentation: **IMPRECISE TERMINOLOGY IDENTIFIED & CORRECTED**. Replaced "simplex-projected" with "nonnegative clamping followed by simplex renormalization".

### 3.3 Interaction Volume (`interaction_volume`)
- **Privacy Unit**: Complete user trajectory within observation window.
- **Adjacency**: Add/remove single user.
- **Per-User Contribution**: Raw interaction counts $m_u \in \mathbb{R}^D_{\ge 0}$.
- **Contribution Bounding**: User-level $L_2$ clipping at bound $C$:
  $$\bar{m}_u = m_u \cdot \min\left(1, \frac{C}{\|m_u\|_2}\right) \implies \|\bar{m}_u\|_2 \le C$$
- **Sensitivity**: Exact $L_2$ sensitivity is:
  $$\Delta_2 = C$$
- **Mechanism**: Analytic Gaussian Vector Mechanism with $\Delta_2 = C$. Coordinates post-processed via $\hat{M}_j = \max(0, \tilde{M}_j)$.
- **Audit Finding**:
  - Implementation: **CORRECT**.
  - Documentation: **CORRECT**.

### 3.4 Success Rate (`success_rate`)
- **Privacy Unit**: Complete user trajectory within observation window.
- **Adjacency**: Add/remove single user.
- **Per-User Contribution**: Total attempts $n_u \in \mathbb{R}^D_{\ge 0}$ and successful interactions $s_u \in \mathbb{R}^D_{\ge 0}$ satisfying coordinate-wise $0 \le s_{u,j} \le n_{u,j}$.
- **Shared User-Level Clipping**:
  $$a_u = \min\left(1, \frac{C_{\text{rate}}}{\|n_u\|_2}\right), \quad \bar{n}_u = a_u n_u, \quad \bar{s}_u = a_u s_u$$
  Preserves $0 \le \bar{s}_{u,j} \le \bar{n}_{u,j}$ and $\|\bar{n}_u\|_2 \le C_{\text{rate}}$.
- **Joint Vector & Sensitivity**:
  $$w_u = \begin{bmatrix} \bar{s}_u \\ \bar{n}_u \end{bmatrix} \in \mathbb{R}^{2D}$$
  $$\|w_u\|_2^2 = \|\bar{s}_u\|_2^2 + \|\bar{n}_u\|_2^2 \le 2 \|\bar{n}_u\|_2^2 \le 2 C_{\text{rate}}^2 \implies \Delta_2 = \sqrt{2} \cdot C_{\text{rate}}$$
  For $C_{\text{rate}} = 20.0$, $\Delta_2 \approx 28.284271247461902$.
- **Mechanism**: Single $2D$-dimensional joint Gaussian release with single RDP charge.
- **Post-Processing**: Total attempts clamped $\hat{N}_j = \max(0, \tilde{N}_j)$, successes clamped $\hat{S}_j = \text{clip}(\tilde{S}_j, 0, \hat{N}_j)$. Rate suppressed if $\hat{N}_j < \tau = \text{min\_noisy\_denominator}$; otherwise $\hat{r}_j = \text{clip}(\hat{S}_j / \hat{N}_j, 0, 1)$.
- **Audit Finding**:
  - Implementation: **CORRECT**.
  - Documentation: **CORRECT**.

### 3.5 Top-K Tasks (`top_k_tasks`)
- **Privacy Unit**: Complete user trajectory within observation window.
- **Adjacency**: Add/remove single user.
- **Candidate Universe**: **Configured finite / dynamic task domain** defined by the active taxonomy ($|T|$ tasks). It is not an open-universe heavy-hitters mechanism.
- **Contribution Bounding**: User task participation is bounded by $k_{\text{tasks}} = \text{max\_tasks\_per\_user}$. Binary vector $v_u \in \{0, 1\}^{|T|}$ has at most $\min(k_{\text{tasks}}, |T|)$ nonzero entries.
- **Sensitivity Truth**:
  - The **tight configured-domain bound** is:
    $$\Delta_2 = \sqrt{\min(k_{\text{tasks}}, |T|)}$$
  - Production calibrates using the **valid conservative $L_2$ sensitivity bound**:
    $$\Delta_2 = \sqrt{k_{\text{tasks}}}$$
  - When $|T| < k_{\text{tasks}}$ (e.g. $|T| = 3, k_{\text{tasks}} = 5$), the conservative calibration is strictly safe but injects more noise than minimal.
- **Mechanism**: Analytic Gaussian Vector Mechanism on task participation counts with $\Delta_2 = \sqrt{k_{\text{tasks}}}$.
- **Post-Processing**: Descending sort with deterministic lexicographical tie-breaking, optional count thresholding, and truncation to top-$k$ entries.
- **Audit Finding**:
  - Implementation: **CORRECT & CONSERVATIVE**.
  - Documentation: **TWO DEFECTS IDENTIFIED & CORRECTED**:
    1. Claim of "unbounded domains" corrected to "dynamically configured long-tail task domain".
    2. Claim of "exact sensitivity $\sqrt{k_{\text{tasks}}}$" corrected to "conservative $L_2$ sensitivity bound $\sqrt{k_{\text{tasks}}}$ (tight domain bound $\sqrt{\min(k_{\text{tasks}}, |T|)}$)".

## 4. Architectural & System Invariants

### 4.1 Lifetime Accounting & Multi-Recipient Scoping
- All five statistics correctly compute an exact RDP privacy cost descriptor ($\rho(\alpha)$ at default RDP orders).
- The persistent SQLite ledger records all committed releases and reservations in `privacy_ledger` and `release_store`.
- Multi-recipient budget isolation (`GLOBAL_EXTERNAL`, `PER_RECIPIENT`, `COLLUSION_GROUP`) prevents cross-scope budget leakage.
- No statistic profile, window parameter, or taxonomy evolution resets historical privacy expenditure.
- Status: **PASS**.

### 4.2 Canonical Replay & Concurrency Memoization
- Semantic release inputs are serialized with canonical key sorting and SHA-256 hashed into `release_key`.
- SQLite `BEGIN IMMEDIATE` transactions with atomic lease fencing prevent concurrent duplicate noise generation.
- Repeated identical queries return cached releases with zero incremental privacy cost.
- Status: **PASS**.

### 4.3 Dynamic Taxonomy
- Taxonomy configuration is managed via `TaxonomyConfig` and serialized to `configs/taxonomy.yaml`.
- Cell names, counts, and index maps dynamically scale to arbitrary Provider $\times$ Task configurations.
- Deterministic SHA-256 fingerprinting guarantees provenance verification.
- Legacy dictionary keys (`grid_3x3`, `share_9d_array`) are maintained exclusively as backward-compatibility fields and do not constrain internal domain dimensions.
- Status: **PASS**.

### 4.4 Continual Observation (Interaction Volume)
- Prefix-stable chronological bounding ($C_{\text{day}}$ and $C_{\text{epoch}}$) enforced online.
- Binary time-tree dyadic decomposition decomposes arbitrary $[s, e]$ intervals into at most $2 \lceil \log_2(T) \rceil$ canonical nodes.
- Memoized canonical tree nodes are reused across sliding-window queries without additional privacy expenditure.
- Status: **PASS**.
