全生命周期隐私政策与 RDP 记账说明

全生命周期隐私预算不是单次查询预算，而是该隐私作用域所有历史 DP 发布经过组合后的累计隐私损失上限。

每次高斯发布 RDP 损失: ρt(α) = αΔt2 / (2σt2)
全生命周期累计组合: ρlife(α) = ∑t ρt(α)
转换最终有效预算: εlife(δ) = minα>1 [ ρlife(α) + ln(1/δ) / (α - 1) ]
  • 单次查询 ε 仅用于校准当前发布的噪声尺度，不等于全生命周期累计 ε。
  • 标准重放（Canonical Replay）：对相同语义参数的重复查询直接复用缓存，严格增加 0 新隐私消耗。
  • 持久化保证：重启系统、更换统计指标或调整 Taxonomy 均不会重置已消耗的历史隐私预算。
  • 政策上限 ε = 4.0：该数值为管理员制定的企业安全治理策略限额，而非算法固定推导的最优数。

步骤 3 设置隐私保护强度

隐私参数 ε（Epsilon）决定了添加到统计结果中的噪声大小。数值越小，隐私保护力度越强；数值越大，统计精度越高。

推荐平衡 (ε = 1.0)
适合常规业务分析与对外发布
较强保护 (ε = 0.5)
适合严格合规场景
较宽松 (ε = 2.0)
适合高精度内部评估
🔒 更强隐私（ε较小，噪声更大） 当前选择：推荐平衡 (ε = 1.0) 📊 更高精度（ε较大，噪声更小）
推荐平衡：在统计可用性与企业员工隐私保护间取得最佳平衡。

企业 LLM 交互日志数据格式规范

系统支持标准 CSV 或 Parquet 格式上传。数据必须按交互记录行组织，且严禁包含员工明文 Prompt、敏感提问或私密交互正文。

字段名称 必填 类型 业务说明与示例值
interaction_id 否 字符串 交互唯一标识符，例如 I_0001
user_id 是 字符串 企业员工或调用账号唯一标识，例如 user_01
timestamp 是 日期时间 调用产生时间，支持 ISO8601 或 YYYY-MM-DD HH:MM:SS
provider 是 字符串 大模型提供方 ID：provider_a, provider_b, provider_c
task 是 字符串 任务分类 ID：technical, document, analysis
success 否 整数/布尔 交互是否成功：1 (成功) 或 0 (失败)
格式示例（CSV 片段）： 
interaction_id,user_id,timestamp,provider,task,success
